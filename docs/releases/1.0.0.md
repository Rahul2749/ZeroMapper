## Supported contract

The first stable release covers flat object mappings generated at compile time:

- Top-level non-generic partial mapper classes with static or instance mapping methods.
- New-object mapping through public parameterless constructors, including public required/init properties.
- Exact case-sensitive property names, supported built-in implicit conversions, and strict nullable checks.
- Public inherited properties, with ambiguous or hidden names rejected.
- Protected destination members, method-specific ignores, and mandatory allow-lists for existing-object updates.
- Deterministic generated source, binding comments, and diagnostics ZM001–ZM007.

The public attributes and documented binding behavior form the 1.x compatibility contract. New opt-in features can be added in minor releases. Breaking API/binding changes require a major release; security fixes can tighten unsafe behavior. Existing 0.0.1-preview.1 mapping declarations continue to use the same syntax.

## Changes since the preview

- Expanded compiler, execution and configuration regression coverage.
- Fixed nullable validation for enclosing generic types and invariant shared references.
- Stable-version packaging and version-specific artifact directories.
- Exact-version package consumer verification on .NET 8 and .NET 10.
- CI verification on both Windows and Linux.
- Stable API documentation and release notes; full usage guide embedded in all packages.
- Package manifests record source commit, working-tree status, sizes, SHA-256 hashes and the passing test-report hash.

## Scope limits

Compatible reference properties, including collections, are assigned shallowly. Nested conversion, collection element mapping, positional constructor binding, flattening, reverse maps, custom converters, projections, runtime mapping and DI helpers are outside the 1.0 contract. There is no performance ratio claim and no claim of verified trimming/AOT support, SourceLink or author signing. Application validation, authorization and transactional update behavior remain the application's responsibility.

## Preparation and verification

Run `pwsh ./eng/prepare-release.ps1`. A passing run writes the three `1.0.0` packages and `release-manifest.json` under `artifacts/packages/1.0.0/`, plus `artifacts/test-results/release-1.0.0.trx`.

Review the manifest and ensure `sourceDirty` is false for the final release build. Do not publish from an uncommitted source snapshot. After upload and indexing, run `pwsh ./eng/verify-public-release.ps1 -Version 1.0.0` against NuGet.org.

## Release verification

- 53 tests passed; Windows and Linux CI both passed for the release source commit.
- The local release was built from a clean committed source snapshot and passed package metadata, README, asset-layout, size-budget and SHA-256 checks.
- After public indexing, the exact 1.0.0 package restored from NuGet.org into fresh .NET 8 and .NET 10 consumers. Both compiled and executed the full documented example successfully.
- The generator did not appear in either application's runtime output.

The artifact hashes and test-report hash are recorded in the release manifest. Public-feed verification evidence is written to `artifacts/public-release-verification-1.0.0.json`.
